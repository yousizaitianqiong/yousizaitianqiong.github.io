当前公司工作：vLLM 推理机制研究与验证规划

机制研究与汇报已完成推测解码压测待验证

已完成连续批处理、PagedAttention、KV Cache 与推测解码的原理梳理和汇报，并形成对照验证路径。当前没有推测解码的实测加速结论。

机制理解

  • 训练与服务：训练阶段更新模型参数；vLLM 将模型产物用于在线推理，负责请求调度、KV Cache 管理和生成执行。
  • Prefill / Decode：Prefill 处理输入并建立历史 token 的 K/V；Decode 逐 token 读取并追加缓存。上下文与并发增加时，缓存占用也会增长。
  • 连续批处理 / PagedAttention：前者按生成迭代组织不同请求，后者按块映射和管理各请求的 KV Cache；分别处理调度与缓存问题。
  • 推测解码：以独立草稿模型为例，草稿先提出候选，目标模型一次前向验证多个位置，按顺序接受有效前缀或修正。接受率、草稿计算及额外缓存成本共同影响最终收益。

验证规划

计划记录 TTFT、TPOT、吞吐、GPU 利用率、显存与 KV Cache 占用、接受率和端到端延迟；对照时保持同一目标模型、负载、采样参数和硬件环境。以上属于验证规划，尚无实测加速结论。
